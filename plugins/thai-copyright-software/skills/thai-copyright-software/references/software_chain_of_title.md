## 1. ขอบเขตรับรอง

ม.8 → เจ้าของแรก ม.9, 10, 14 → การโอน ม.17 **ทุกช่วงต้องมีฐานหรือเอกสาร** พิสูจน์ใครสร้าง เข้า ม.8 สิทธิมาถึงบริษัทอย่างไร และสิทธิบุคคลที่สามจำกัดโมเดลธุรกิจหรือไม่ รับรองเพียง “ไม่พบช่องว่างในขอบเขตที่ตรวจ” ไม่ใช่ title สะอาดสมบูรณ์

## 2. Inventory/ผู้พัฒนา

เก็บ repo/fork/submodule commit และตัวตน Git → บุคคลจริง; UI/ฟอนต์/ข้อมูล/โมเดล; บอท/CI; lockfile/โค้ดซื้อ; ช่วงก่อน/หลังตั้งบริษัท/ข้อตกลง IP; ถิ่นผู้เขียน

| ประเภท | ฐาน/เครื่องมือ |
|---|---|
| A ผู้ก่อตั้งก่อนตั้งบริษัท | ม.8; โอนหลังบริษัทเกิด + ศีลธรรม |
| B ลูกจ้าง | ม.9; ข้อตกลงหนังสือ + โอนสำรอง; งานเก่ายืนยัน |
| C ผู้รับจ้าง/ฟรีแลนซ์/นักออกแบบ | ม.10; ยืนยันขอบเขต วัสดุเดิมและสิทธิผู้รับจ้างช่วง |
| D ฝึกงาน/นักศึกษา/สังกัดผู้อื่น | ตรวจความสัมพันธ์ ม.8, 9, 10; ผู้แทนผู้เยาว์/นายจ้างหรือสถาบันเดิม |
| E ผู้ร่วมพัฒนาต่างประเทศ | ม.8, 61 + กฎหมายถิ่น; โอนจากเจ้าของจริง |
| F OSS ภายนอก | licence โครงการ; CLA/DCO ตามวัตถุประสงค์ ไม่ถือว่าโอนแล้ว |
| G บอท/AI | ตามมนุษย์/เครื่องมือ/ส่วนเครื่องสร้าง บันทึกและตรวจที่มา |
| H โค้ดซื้อ | ห่วงโซ่ผู้ขาย หนังสือโอน คำรับรองต้นทาง |
| I งานร่วมคู่ค้า | ม.19 วรรคสอง; เทียบ ป.พ.พ. ม.1357, 1361 ต้องตรวจแนวศาล ข้อตกลงทุกเจ้าของ |

## 3. หลักฐาน ม.8

ต่อผู้เขียน: สัญชาติ/ถิ่นที่อยู่ **ตลอดหรือส่วนใหญ่ช่วงสร้าง**; ประเทศ/วันที่โฆษณาครั้งแรก หรือการโฆษณาในไทย/ภาคีภายใน 30 วัน; สถานะประเทศ ม.61 “โฆษณา” ม.4 เป็นนิยามเฉพาะ ไม่ใช้ที่ตั้งเซิร์ฟเวอร์/วัน commit แทน บันทึกหลักฐานที่ตรวจใน `templates.md` ข้อ 3 ไม่เก็บข้อมูลส่วนบุคคลเกินจำเป็น

## 4. เอกสาร/แก้ช่องว่าง

ตรวจสองลายมือชื่อ อายุ งาน ขอบเขต สิทธิเรียกร้อง ศีลธรรม ความสามารถ อำนาจ/ผลประโยชน์ขัดกัน วันที่จริง/กฎหมายถิ่น ตาม `assignment_licensing_and_moral_rights.md`

แก้ด้วยโอนใหม่/ยืนยัน + อนุญาตการใช้เดิม ไม่ให้สัตยาบันทำเอกสารโมฆะขาดแบบฟื้นย้อนหลัง; หนังสือยินยอมจากเจ้าของเดิม; licence ระหว่างรอจากผู้มีสิทธิ; งานติดขัดอาจเขียนใหม่ clean-room; ดีลใช้ disclosure/คำรับรอง/ชดใช้/เงื่อนไขก่อนปิด → `thai-legal-due-diligence`, `thai-contract-master`

## 5. OSS/SBOM

**5.1 ฐานไทย:** ใช้เป็น licence ตาม ม.15(5) จากเจ้าของแต่ละราย ไม่ใช่โอน ไม่ใช่ public domain ฝ่าฝืนอาจเกินอนุญาต ม.27, 30 หรือผิดสัญญา ต้องแยกเงื่อนไข ยังไม่ยืนยันคำพิพากษาไทยเฉพาะการบังคับ OSS

**5.2 อ่านเวอร์ชันจริง** (สรุปข้อความ licence; ไม่ใช่กฎหมายไทย):

| licence | ภาระที่ต้องตรวจ |
|---|---|
| MIT | รักษาประกาศลิขสิทธิ์/อนุญาตในสำเนาหรือส่วนสาระสำคัญ; sublicense ได้ |
| Apache-2.0 §§2–5 | สิทธิลิขสิทธิ์ถาวร/เพิกถอนไม่ได้; patent grant มีเงื่อนไขสิ้นสุดเมื่อฟ้องตาม §3; สำเนา licence ระบุไฟล์แก้ รักษาประกาศ/NOTICE ที่เกี่ยวข้อง; contributions ตาม §5 เว้นตกลงต่าง |
| GPL-3.0 §§5–6 | convey งานที่ครอบคลุมต้อง GPL และ Corresponding Source ตามวิธีของ §6 ไม่เหมารวมว่าทุกโปรแกรมที่ติดตั้งร่วมต้อง GPL |
| AGPL-3.0 §13 | เมื่อแก้โปรแกรมและผู้ใช้โต้ตอบผ่านเครือข่าย ต้องเสนอ Corresponding Source ของเวอร์ชันนั้นแก่ผู้ใช้ตามเงื่อนไข |
| MPL-2.0 §§3.1–3.3 | Source Code Form ใต้ MPL; แจก Executable ต้องมีวิธีรับ source; larger work แยกเงื่อนไข ไม่เหมารวมทุกไฟล์ต้อง MPL |

ไม่มี licence อย่าสันนิษฐานสิทธิใช้นอกข้อยกเว้น ตัวกระตุ้น: แจกจ่าย แก้ไข เครือข่าย และรวม/เชื่อมโค้ด วิเคราะห์โครงสร้างจริง GPL ไม่ใช่ AGPL และ SaaS ไม่ตัดทุกภาระอัตโนมัติ

**5.3 MIT → Apache:** การเปลี่ยนรุ่นใหม่ไม่ลบสิทธิที่ให้ไปแล้ว; Apache §2/GPL §2 ระบุการให้สิทธิเพิกถอนไม่ได้ตามเงื่อนไข MIT ต้องอ่านขอบเขต sublicense ไม่อ้างว่าประกาศบริษัทถอนสิทธิย้อนหลังได้

จำแนกส่วนบริษัท/ผู้ร่วม/ไลบรารี; มีสิทธิเพียงอนุญาตไม่อ้างเป็นเจ้าของ ส่วน MIT sublicense ได้แต่คงประกาศเดิม ไม่แสดงว่าเจ้าของเดิมให้ patent grant Apache เอง GPL §2 ไม่อนุญาต sublicense หลีกเลี่ยงนำเข้า Apache อย่างเดียวโดยไม่ตรวจ compatibility/ขอยินยอม CLA relicense ตามขอบเขตเท่านั้น แก้ LICENSE/NOTICE/header วันที่จริง เก็บหลักฐานเวอร์ชันเก่าและคำยินยอม

**5.4 CLA/DCO:** CLA เป็นสัญญา grant/โอนและอาจ relicense/dual-license ตามข้อความ โอนต้องครบ ม.17; DCO v1.1 รับรองว่ามีสิทธิส่งงานภายใต้ licence ที่ระบุและยอมรับการเก็บบันทึก ไม่ให้สิทธิเพิ่มเอง ไม่พอแทนการโอนหรืออำนาจเปลี่ยน licence ทุกกรณี

**5.5 SBOM แนวปฏิบัติ ไม่ใช่หน้าที่กฎหมายไทยทั่วไป:** component/เวอร์ชัน ผู้ผลิต ที่มา licence/SPDX ID hash ความสัมพันธ์ แก้หรือไม่ วิธีแจก; อ่าน lockfile/scanner ร่วมกับมนุษย์ ตรวจฟอนต์/ภาพ/โมเดล/ข้อมูลและ snippet ด้วย รูปแบบ SPDX/CycloneDX เลือกตามคู่ค้า ไม่รับรองว่า scanner ไม่พบแล้วไม่ละเมิด

## 6. ชุดปิดดีล

**Manifest:** ทะเบียน `templates.md` ข้อ 8; โอน/ยืนยัน/ศีลธรรม; ข้อกำหนดจ้าง/ผู้ร่วม; สิทธินายจ้างเดิม; ม.8; SBOM/NOTICE/CLA/DCO; AI; มติ/อำนาจ; disclosure พร้อมขอบเขตรับรอง

🔴 ผู้สร้างหลักไม่ทราบ/ไม่มีเอกสาร โอนวาจา ไม่ระบุอายุ วันย้อนหลัง copyleft ขัดวิธีแจกจริง
🟡 ลายมือชื่อไม่ครบ ศีลธรรม ผู้เยาว์/กฎหมายถิ่นยังไม่ตรวจ
📝 ช่องว่างทุกข้อมีเจ้าของงาน กำหนดและหลักฐานปิด ไม่เปลี่ยนเป็นเขียวเพียงได้คำรับรองผู้ขาย

## 7. ตัวอย่าง

**ผู้ก่อตั้งก่อนจดบริษัท:** ตรวจ ม.8, 61 นายจ้างเดิม/ผู้ร่วม/OSS/AI ไม่สันนิษฐานบริษัทมี licence → โอนตลอดอายุหลังตั้ง + ศีลธรรม + อำนาจ/ผลประโยชน์ขัดกัน ป.พ.พ. ม.805, 1185 → `thai-corporate-secretarial`; ภาษีจากการโอน ในประเทศ `thai-tax-revenue-code` ข้ามพรมแดน `thai-tax-international`

**ผู้รับจ้างทำแอปไม่มีหนังสือ:** ม.10 ผู้ว่าจ้างถือสิทธิหากพิสูจน์การรับจ้าง/ไม่มีข้อตกลงอื่นจากใบสั่ง อีเมล เงิน แต่ไม่เหมารวมวัสดุเดิม/จ้างช่วง → ยืนยันสิทธิ + licence วัสดุเดิม + ศีลธรรม + SBOM ปฏิเสธ → เก็บพยานให้ `thai-litigation-caseprep`
