## 1. ROPA และกิจการเล็ก

**controller ม.39(1)–(8):** ข้อมูลที่เก็บ; วัตถุประสงค์รายประเภท; controller; retention; สิทธิ/วิธี/เงื่อนไขเข้าถึง; ใช้/เปิดเผยที่ยกเว้น consent; ปฏิเสธคำขอ/คัดค้าน; คำอธิบายความปลอดภัย ทำหนังสือ/อิเล็กทรอนิกส์ให้เจ้าของข้อมูล/สคส.ตรวจได้ ใช้กับตัวแทนโดยอนุโลม

**processor ม.40(3) + ประกาศ พ.ศ. 2565 ข้อ 3** (มีผล 17 ธ.ค. 2565): รายกิจกรรมต้องมี processor/ตัวแทน; controller/ตัวแทนที่ทำแทน; DPO/ช่องทาง; ประเภท/ลักษณะประมวลผล ข้อมูลและวัตถุประสงค์ที่มอบ; ประเภทผู้รับต่างประเทศ; มาตรการความปลอดภัย เก็บเป็นหนังสือ/อิเล็กทรอนิกส์ เข้าถึงง่าย แสดงต่อ สคส./controller/ผู้ได้รับมอบหมายได้รวดเร็ว

**ประกาศยกเว้น พ.ศ. 2567 สองฉบับ:** controller มีผล **8 เม.ย. 2568** แทน พ.ศ. 2565; processor **9 ม.ค. 2568** ไม่ยก DPA/ความปลอดภัย/สิทธิ

```text
เป็นกิจการตามประเภทที่ประกาศ? ไม่ -> ทำ ROPA
ใช่ -> ต้องมี DPO ม.41(1)-(3)? ใช่ -> ไม่ได้รับยกเว้น
ไม่ -> กิจกรรมเสี่ยงต่อสิทธิ / ไม่ใช่ครั้งคราว / ข้อมูล ม.26? ใช่ -> ทำ ROPA กิจกรรมนั้น
ไม่ -> ยกเว้นเฉพาะรายการที่ระบุ; controller ยังเก็บปฏิเสธคำขอ ม.39(7)
```

ประเภทกิจการ: SME; วิสาหกิจชุมชน/เครือข่าย; วิสาหกิจเพื่อสังคม/กลุ่ม; สหกรณ์/ชุมนุม/เกษตรกร; มูลนิธิ/สมาคม/ศาสนา/เอกชนไม่แสวงกำไร; นิติบุคคลอาคารชุด/หมู่บ้านจัดสรร; ครัวเรือนหรือทำนองเดียวกัน; บุคคลธรรมดา

ประเภท SME ใช้กฎกระทรวง พ.ศ. 2562 ข้อ 2–5 ไม่ใช่ทุกประเภทต้องทดสอบจำนวนคน: ผลิตเล็ก ≤50 คนหรือรายได้ ≤100 ล้านบาท กลาง >50–200 คนหรือ >100–500 ล้านบาท; บริการ/ค้าส่ง/ปลีกเล็ก ≤30 คนหรือ ≤50 ล้านบาท กลาง >30–100 คนหรือ >50–300 ล้านบาท ถ้าจำนวนคนกับรายได้เข้าคนละประเภท **รายได้เป็นเกณฑ์** ไม่เปลี่ยน "หรือ" เป็น "และ" ตรวจหลักฐานงบ/การจ้างและฉบับปัจจุบันก่อนอ้างยกเว้น

## 2. ผู้ประมวลผลและ DPA

ม.40(1) ทำตามคำสั่งเว้นขัดกฎหมาย; (2) ความปลอดภัย/แจ้ง controller เมื่อเกิดเหตุ; (3) ROPA; วรรคสองทำผิดคำสั่งถือเป็น controller ส่วนนั้น; **วรรคสาม controller ต้องจัดให้มีข้อตกลง**; วรรคสี่ (ท้าย) เป็น SME ROPA exemption ไม่ใช่ DPA ม.37(2) กำหนด controller กันผู้รับใช้/เปิดเผยมิชอบ

| ประเด็น DPA | ที่มา/สิ่งที่ควรเขียน |
|---|---|
| ขอบเขต/คำสั่ง | ม.40: วัตถุประสงค์ ข้อมูล เจ้าของ ระยะเวลา คำสั่ง; แจ้งเมื่อคำสั่งมิชอบ |
| ความปลอดภัย | ม.40(2), ประกาศความปลอดภัย ข้อ 6: ไม่ต่ำกว่าข้อ 4; ผูกพันผู้เข้าถึง |
| แจ้งเหตุ | ประกาศแจ้งเหตุ ข้อ 8: **โดยไม่ชักช้าภายใน 72 ชั่วโมงนับแต่ processor ทราบเท่าที่ทำได้**; สัญญาควรให้เร็วพอที่ controller แจ้งได้ทัน ไม่รอจนเพดาน |
| สิทธิ/หลักฐาน | วิธีช่วยค้น/สำเนา/แก้/ลบ/ระงับ; ROPA; หลักฐานมาตรการ |
| โอน | ประเทศ ผู้รับ เครื่องมือ ม.28–29 และโอนต่อ; แจ้งคำขอรัฐเท่าที่กฎหมายอนุญาต |
| own use/training | ข้อห้ามและขอบเขตตามคำสั่ง; เปลี่ยนบทบาทไม่ทำให้ own use ชอบเอง |
| ข้อเพิ่มเติม | sub-processor authorisation/flow-down/รับผิด; audit; คืน/ลบ/ยืนยัน; liability/ลำดับเอกสาร เป็นข้อตกลงให้หน้าที่ทำได้ ไม่อ้างทุกข้อเป็นรายการบังคับใน ม.40 |

GDPR Art.28 ใช้เมื่อเข้าเกณฑ์ของฝั่ง EU เพิ่มตามจริง ไม่ใช้ DPA ต่างประเทศโดยไม่เทียบหน้าที่ไทย; แนวทาง AI ทางการเป็นคำแนะนำ ไม่ใช่ร่างเดือน ก.พ. หรือหน้าที่ลบ model weights ทุกกรณีโดยอัตโนมัติ

## 3. DPO

**ม.41(1)–(3):** หน่วยงานรัฐตามประกาศ; กิจกรรมหลักตรวจข้อมูล/ระบบสม่ำเสมอโดยมีข้อมูลจำนวนมาก; กิจกรรมหลักข้อมูล ม.26 รายชื่อรัฐ พ.ศ. 2566 และฉบับ 2 พ.ศ. 2568 ใช้ 16 ต.ค. 2566/8 ธ.ค. 2568 ตามลำดับ ตรวจบัญชี ไม่เหมารวมทุกหน่วยงานรัฐ

ประกาศ ม.41(2) พ.ศ. 2566 (มีผล 13 ธ.ค. 2566) ข้อ 4 ต้องครบ **กิจกรรมหลัก + ตรวจสม่ำเสมอ + จำนวนมาก**:
- กิจกรรมหลัก: จำเป็น/สำคัญต่อเป้าหมาย ไม่ใช่งานสนับสนุน
- ข้อ 5: systematic/regular tracking, monitoring, profiling; รวมบัตรสมาชิก/โดยสาร ตรวจคุณสมบัติ/credit scoring/ป้องกันฉ้อฉล โฆษณาพฤติกรรม เครือข่าย/โทรคมนาคม และเฝ้าระวังสถานที่ ตามเงื่อนไข
- ข้อ 6: จำนวน/สัดส่วนคน ปริมาณ/ประเภท ระยะเวลา/ความคงอยู่ ขอบเขตพื้นที่/ประเทศ; ถือว่าจำนวนมากเมื่อกิจกรรมหลัก **≥100,000 ราย**, โฆษณาพฤติกรรมผ่าน search/social media ที่ใช้กว้าง, ลูกค้าประกัน/สถาบันการเงิน และโทรคมนาคมแบบที่สามตามบท ยกข้อมูลเครดิตตามเงื่อนไข
- ข้อ 7: คำนึงมาตรฐานกิจการและความเสี่ยง; ต่ำกว่า 100,000 ไม่รับรองว่าไม่ต้อง DPO

```text
รัฐในบัญชี หรือกิจกรรมหลัก ม.26? -> DPO
อื่น: กิจกรรมหลัก + ตรวจสม่ำเสมอ (ข้อ 5) + จำนวนมาก (ข้อ 6)? -> DPO
ไม่ครบ -> ไม่เกิดหน้าที่จาก ม.41(2) เพียงเพราะมี 100,000 ราย; ประเมินกิจกรรมอื่นด้วย
```

**ม.41–42:** ลูกจ้าง/ผู้รับจ้างได้ ตั้งร่วมในเครือเมื่อทุกแห่งติดต่อสะดวก แจ้งข้อมูล/ช่องทางแก่เจ้าของ/สคส. หน้าที่ให้คำแนะนำ ตรวจการปฏิบัติ ประสาน สคส. รักษาลับ; ให้เครื่องมือ/เข้าถึงข้อมูล รายงานผู้บริหารสูงสุดโดยตรง ห้ามเลิกจ้างเพราะทำหน้าที่ งานอื่นต้องไม่ขัดแย้งและรับรองต่อ สคส.ตามข้อ 8 ไม่ใช้ผู้ตัดสิน purpose ตรวจตนเองโดยไม่มีการแก้ conflict (การวิเคราะห์)

## 4. จุดเสี่ยงและตัวอย่าง

จุดเสี่ยง: อ้าง SME ทั้งที่ processing ประจำ/อ่อนไหว; ไม่มี ม.39(7); นาฬิกา processor เริ่มเมื่อสอบสวนจบ; DPO = ตัวแทนต่างประเทศ; ผู้ให้บริการใช้เนื้อหาลูกค้าปรับสินค้าเอง

(การวิเคราะห์) SaaS ขนาดเล็กประมวลผล HR ทุกเดือน: ไม่ใช่ครั้งคราวจึงอย่าอ้างยกเว้น ROPA ตามขนาดเพียงอย่างเดียว DPO ต้องตรวจ core/regular/large และข้อมูลอ่อนไหวแยก; เอกสารข้อตกลงยังต้องมี แม้เข้า ROPA exemption บางกิจกรรม
