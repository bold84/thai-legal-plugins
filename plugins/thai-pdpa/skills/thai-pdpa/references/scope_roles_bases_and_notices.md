## 1. ขอบเขตและการยกเว้น

| มาตรา | การทดสอบ |
|---|---|
| 3 | กฎหมายเฉพาะใช้ก่อน; PDPA เสริมเรื่องข้อมูล/สิทธิ/โทษและร้องเรียนตามเงื่อนไข |
| 4(1)–(6) | ส่วนตัว/ครอบครัว; งานรัฐด้านความมั่นคง/ฟอกเงิน/นิติวิทยาศาสตร์/ไซเบอร์; สื่อ/ศิลปะ/วรรณกรรมตามเงื่อนไข; รัฐสภา; ศาล/ยุติธรรมอาญา; ข้อมูลเครดิต |
| 4 วรรคสอง–สาม | ยกเว้นเพิ่มต้อง พ.ร.ฎ.; ผู้ยกเว้นตาม (2)–(6)/พ.ร.ฎ.ยังมีมาตรฐานความปลอดภัย |
| 5 วรรคหนึ่ง | controller/processor อยู่ไทย ไม่ว่าประมวลผลในหรือนอกไทย |
| 5 วรรคสอง | นอกไทย แต่เสนอสินค้า/บริการแก่คนในไทยหรือเฝ้าติดตามพฤติกรรมในไทย; ไม่ใช้สัญชาติหรือการจ่ายเงินเป็นเงื่อนไข |
| 6 | ระบุตัวบุคคลธรรมดาโดยตรง/อ้อม; ไม่รวมข้อมูลผู้ตายโดยเฉพาะ; pseudonymised ไม่ใช่นิรนามเอง |

```text
ระบุตัวได้? ไม่ -> นอกนิยาม ม.6
ใช่ -> ผู้ประมวลผล/ควบคุมอยู่ไทย? ใช่ -> ม.5 วรรคหนึ่ง
       ไม่ -> คนอยู่ไทย + เสนอสินค้า/บริการหรือเฝ้าติดตามในไทย? -> ม.5 วรรคสอง
แล้วตรวจ ม.3/4 และ พ.ร.ฎ.เป็นรายกิจกรรม -> บทบาท -> ฐาน -> หน้าที่
```

**processor ไทยรับข้อมูลต่างชาติ:** ม.5 วรรคหนึ่งไม่แยกสัญชาติ/แหล่งข้อมูล จึงต้อง ม.40 แม้ controller ต่างประเทศไม่เข้า ม.5 วรรคสอง (การวิเคราะห์จากตัวบท); ส่งกลับ/เปิด remote access ต่างประเทศประเมินการโอนราย flow ไม่ยกเว้นอัตโนมัติ

**พ.ร.ฎ.ยกเว้น พ.ศ. 2566:** มีผล 14 ม.ค. 2567 ยกหมวด 2–3 เฉพาะกิจกรรมตาม ม.6–12 เช่น ทุจริต ภาษี/ศุลกากร/สรรพสามิต งานรัฐที่ระบุ และความร่วมมือยุติธรรม/เนรเทศ/ส่งผู้ร้ายข้ามแดน; ม.4 จำกัดอำนาจ/คำขอและสงวนร้องเรียน ม.5 ความปลอดภัย ม.13 ตีความ ไม่คุ้มครองการกระทำมิชอบ เอกชนส่งให้รัฐไม่รับข้อยกเว้นของรัฐมาใช้เอง → TIA ใน `cross_border_transfers_and_tia.md`

## 2. บทบาท

ม.6: controller ตัดสินเก็บ/ใช้/เปิดเผย; processor ทำตามคำสั่งหรือในนาม ไม่ใช่ตามชื่อสัญญาอย่างเดียว ทำผิดคำสั่ง ม.40(1) ถือเป็น controller ของส่วนนั้น (วรรคสอง)

| กิจกรรมตัวอย่าง | วิเคราะห์บทบาท |
|---|---|
| payroll outsource ตามคำสั่ง | processor; ใช้ benchmark เพื่อตนต้องตรวจบทบาท/ฐานแยก |
| SaaS tenant content / บัญชี / training | อาจ processor / controller / controller แยก ตามอำนาจจริง |
| บริษัทในเครือแบ่งข้อมูล | ไม่ถือว่าเป็นคนเดียวกัน; BCR ไม่ใช่ฐานประมวลผล |
| ร่วมกำหนดวัตถุประสงค์ | แบ่งหน้าที่ notice/สิทธิ/เหตุ/โอนเป็นหนังสือ (แนวปฏิบัติ); PDPA ไม่มีบท joint controllers แบบ GDPR Art.26 |

ทดสอบ: ใครกำหนดวัตถุประสงค์/ข้อมูล ใครใช้เพื่อตน ใครสั่งลบ/เปิดเผย; vendor อาจมีหลายบทบาทต่อข้อมูลต่างส่วน

## 3. ข้อมูลอ่อนไหวและผู้เยาว์

**ม.26:** เชื้อชาติ เผ่าพันธุ์ ความเห็นการเมือง ลัทธิ/ศาสนา/ปรัชญา พฤติกรรมทางเพศ ประวัติอาชญากรรม สุขภาพ ความพิการ สหภาพแรงงาน พันธุกรรม ชีวภาพ และประเภทที่ประกาศ ต้องยินยอมชัดแจ้งหรือข้อยกเว้น: ชีวิตเมื่อยินยอมไม่ได้; non-profit ตามเงื่อนไข; เจ้าของเปิดสาธารณะโดยยินยอมชัดแจ้ง; สิทธิเรียกร้อง; การปฏิบัติตามกฎหมายเฉพาะเรื่องตาม (5) พร้อมมาตรการ ห้ามใช้ ม.24(5) แทน

- ประวัติอาชญากรรม: ประกาศ พ.ศ. 2566 ข้อ 5–9 ใช้ 7 เม.ย. 2567; กฎหมายบังคับตรวจ หรือยินยอมชัดแจ้งสำหรับเป้าหมายที่ระบุ เช่น รับเข้าทำงาน ตรวจคุณสมบัติ; แจ้งความจำเป็นตั้งแต่รับสมัคร เก็บหลังดำเนินการเสร็จไม่เกิน 6 เดือน เว้นยินยอมชัดแจ้งเป็นอย่างอื่น ยังจำกัดเท่าที่จำเป็น
- ชีวภาพ: เทคนิคที่ใช้ลักษณะกายภาพ/พฤติกรรมยืนยันตัวเฉพาะ ไม่ใช่ภาพใบหน้าทุกภาพอัตโนมัติ; ปิดศาสนาในบัตรเมื่อไม่จำเป็น ระวัง consent ลูกจ้างไม่อิสระ

**ม.20:** ผู้เยาว์ที่ไม่บรรลุนิติภาวะโดยสมรส/ไม่มีฐานะ ป.พ.พ. ม.27 หากการนั้นทำเองไม่ได้ตาม ป.พ.พ. ม.22–24 ต้องผู้ใช้อำนาจปกครองด้วย; อายุไม่เกิน 10 ปีผู้ปกครองให้แทน; ไร้/เสมือนไร้ความสามารถผู้อนุบาล/ผู้พิทักษ์ ใช้กับถอน/แจ้ง/สิทธิ/ร้องเรียนโดยอนุโลม ไม่แปลว่าข้อมูลเด็กทุกกิจกรรมต้องใช้ consent; ยังเลือกฐานกฎหมายให้ตรงก่อน

## 4. ฐานและความยินยอม

| ม.24 | ฐานไม่ต้องยินยอม | จุดตรวจ |
|---|---|---|
| (1) | จดหมายเหตุ/วิจัย/สถิติ | มาตรการตามประกาศ พ.ศ. 2566; ไม่เหมารวม training เชิงพาณิชย์ |
| (2) | ชีวิต/ร่างกาย/สุขภาพ | ความจำเป็นจริง |
| (3) | สัญญา/คำขอก่อนสัญญา | เจ้าของข้อมูลเป็นคู่สัญญาและข้อมูลจำเป็น |
| (4) | ภารกิจสาธารณะ/อำนาจรัฐ | ระบุอำนาจที่อ้าง |
| (5) | ประโยชน์โดยชอบ | ชั่งสิทธิขั้นพื้นฐาน; LIA เป็นแนวปฏิบัติ; คัดค้าน ม.32(1) |
| (6) | ปฏิบัติตามกฎหมาย | ระบุกฎหมาย/ข้อมูลที่จำเป็น ไม่อ้างนโยบายบริษัทเป็นกฎหมาย |

ม.19: ขอ consent ก่อน/ขณะเก็บ ใช้ เปิดเผย ชัดแจ้ง เป็นหนังสือ/อิเล็กทรอนิกส์เว้นโดยสภาพทำไม่ได้; แยกข้อความ อ่านง่าย ไม่หลอก อิสระ ไม่ผูกบริการกับข้อมูลไม่จำเป็น ถอนง่ายเท่าให้และแจ้งผล การยินยอมไม่ชอบไม่ผูกพัน บันทึกข้อความเวอร์ชัน ผู้ให้ เวลา/ช่องทาง วัตถุประสงค์และถอน (แนวปฏิบัติ)

ม.21–22: ใช้ตามวัตถุประสงค์ที่แจ้ง; ใหม่ต้องแจ้งและยินยอมก่อนเว้นกฎหมาย; เก็บเท่าที่จำเป็น ม.27: ใช้/เปิดเผยตามฐานที่ชอบ ผู้รับจำกัดวัตถุประสงค์ และบันทึกกิจกรรมที่ยกเว้น consent ตาม ม.39

## 5. การแจ้งและตลาดแบบตรง

**ม.23 ก่อน/ขณะเก็บ เว้นรู้แล้ว:** (1) วัตถุประสงค์/ฐาน (2) ต้องให้ตามกฎหมาย/สัญญาหรือไม่/ผล (3) ข้อมูล/retention (4) ประเภทผู้รับ (5) controller/ตัวแทน/DPO/ช่องทาง (6) สิทธิ; แม่แบบ `templates.md` ข้อ 1 ไม่ใช้ notice แทน consent

**ม.25 แหล่งอื่น:** แจ้งไม่ชักช้าไม่เกิน 30 วัน; ใช้ติดต่อแจ้งครั้งแรก เปิดเผยแจ้งก่อนครั้งแรกตามเงื่อนไข; ตรวจ consent/ข้อยกเว้นตามบท กรณีแจ้งไม่ได้/อุปสรรคต้องพิสูจน์และมีมาตรการ ไม่ใช่ dataset ใหญ่จึงพ้นเอง

**ม.32(2):** ตลาดแบบตรงคัดค้านได้ทุกเมื่อ ไม่หักล้างด้วยประโยชน์สำคัญกว่า หยุด/แยกตามวรรคสอง ทำ suppression list (แนวปฏิบัติ); โฆษณาผู้บริโภค → `thai-ecommerce-consumer` คุกกี้ไม่มีบท PDPA เฉพาะ วิเคราะห์ ม.19/23/24 และแนวทางปัจจุบัน

## 6. จุดเสี่ยงและตัวอย่าง

จุดเสี่ยง: consent ยัดใน terms; สัญญากับนิติบุคคลใช้แทนฐานของบุคคลอื่น; notice เฉพาะบนเว็บที่ไม่ทำให้ทราบ; ใช้ข้อมูลอ่อนไหวเพราะ "อยู่บนอินเทอร์เน็ต"; เปลี่ยน purpose/เก็บตลอดไป

(การวิเคราะห์) บริษัทจัดอบรมส่งรายชื่อพนักงานให้ SaaS: แยกฐานบริษัทกับ vendor processor; ไม่อ้างสัญญาระหว่างสองบริษัทเป็น ม.24(3) ของพนักงานทันที ถ้า vendor ฝึกโมเดลเองต้องประเมินบทบาท วัตถุประสงค์/ฐาน/notice และโอนเพิ่ม ไม่ใช่แก้คำเรียกใน DPA แล้วจบ
