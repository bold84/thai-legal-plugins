## 1. วิธีจำแนก 3 ขั้นของ DFT (ข่าว 27 เม.ย.2569 [S8])
1. พิกัดที่ส่งออก + Technical Data Sheet → 2. ค้น https://etcwmd.dft.go.th/e-classification → 3. เทียบพารามิเตอร์ Control List
- พิกัดเข้าข่ายไม่ใช่ DUI อัตโนมัติ; เปิดนิยาม/Technical Note ให้วิศวกรยืนยัน เก็บผลค้น/ฉบับบัญชี
- CAC 2564 ข้อ 2 ซอฟต์แวร์ระบุรหัส DUI และพิกัดสื่อเมื่อมีสื่อ ไม่ใช้พิกัดสื่อแทนการจำแนกหรืออนุมานว่าทุกไฟล์มีใบขน [S5]

## 2. โครงสร้าง NCL และหมวด 5 [S2]
- บัญชี 1: **0** นิวเคลียร์ · **1** วัสดุพิเศษ · **2** แปรรูปวัสดุ · **3** อิเล็กทรอนิกส์ · **4** คอมพิวเตอร์ · **5** โทรคมนาคม/ความปลอดภัยข้อมูล · **6** เซนเซอร์/เลเซอร์ · **7** นำร่อง/avionics · **8** ทางทะเล · **9** การบินอวกาศ/ขับดัน; บัญชี 2 สินค้าสงสัยการใช้สุดท้าย
- รหัส: หมวด + **A** ระบบ/อุปกรณ์ **B** ทดสอบ/ผลิต **C** วัสดุ **D** ซอฟต์แวร์ **E** เทคโนโลยี + เลขรายการ; คล้าย EU ไม่ใช่รับกฎหมาย EU มาใช้ ใบอนุญาตไทยยังเฉพาะ 0A/0B/0C [S3]
- บัญชีรายการสินค้าควบคุมแห่งชาติ (NCL 2569) ปรับปรุง/ทบทวนอย่างน้อยทุก **5 ปี** (มติ คกก. ส่งออก 1/2569, 10 พ.ย. 2568); โครงสร้างหมวด 0–9/กลุ่ม A–E คู่ขนานกับ EU dual-use; **อย่าระบุ “ฉบับ Wassenaar/EU ปีใด”** จนกว่าภาคผนวกของ NCL เองจะระบุ (ยังตรวจสอบไม่ได้) [S2/S8]
- ส่วน 1 โทรคมนาคม เช่น 5A001/5B001/5D001/5E001; ส่วน 2 information security ดังตาราง (ต้องเปิดข้อย่อย/หมายเหตุจริง)

| รายการ | จุดตรวจ |
|---|---|
| 5A002 | a รักษาความลับข้อมูล; b โทเคนเปิดเข้ารหัส; c QKD; d UWB; e spread spectrum |
| 5A003/5A004 | ไม่ใช้เข้ารหัส: เคเบิลตรวจบุกรุก/ลด compromising emanations; cryptanalysis/สกัดข้อมูลดิบ/หลบ authentication |
| 5B002 | ทดสอบ/ผลิตรายการที่ระบุ |
| 5D002 | a พัฒนา/ผลิต/ใช้รายการที่ระบุ; b คุณลักษณะโทเคน; c ทำ/จำลอง 5A002.a/c/d/e, 5A003/5A004 |
| 5E002 | a เทคโนโลยีตาม GTN ของอุปกรณ์/ซอฟต์แวร์ที่ระบุพร้อมข้อยกเว้น; b คุณลักษณะโทเคน 5A002.b |

5D002.c.1 มีข้อไม่ควบคุม OAM-only ที่ใช้มาตรฐานเข้ารหัสเผยแพร่/เชิงพาณิชย์; c.3.b ไม่ควบคุม intrusion software อย่าเหมารวมเครื่องมือไซเบอร์ทุกชนิด

## 3. พารามิเตอร์ 5A002.a และ Technical Notes [S2]
- ออกแบบ/ดัดแปลงใช้ **cryptography for data confidentiality** ด้วยอัลกอริทึมที่กำหนด เปิดแล้วหรือเปิดได้โดย cryptographic activation ที่ไม่ใช้กลไกปลอดภัย และตรง **a.1** security เป็นหลัก **a.2** สื่อสารดิจิทัล/เครือข่าย **a.3** เก็บ/ประมวลข้อมูลเป็นหลัก **a.4** อื่นที่เข้ารหัสไม่ใช่หลักและอาศัยอุปกรณ์/ซอฟต์แวร์ควบคุมแยกในส่วน 2
- **ไม่นับ:** authentication, signature, integrity, non-repudiation, DRM/กันสำเนา, เข้ารหัสเพื่อบันเทิง/ออกอากาศพาณิชย์/เวชระเบียน และ key management สนับสนุนเฉพาะฟังก์ชันเหล่านี้
- **อัลกอริทึมที่กำหนด:** สมมาตรกุญแจ **>56 บิต** ไม่รวม parity; อสมมาตร integer factorisation **>512 บิต**/finite-field discrete logarithm **>512 บิต**/กลุ่มอื่น **>112 บิต**; lattice/isogeny/random codes เช่น Kyber/McEliece
- Note 1 หน่วยงานเรียกข้อมูลคุณลักษณะ/ความสามารถได้; Note 2 มีข้อเฉพาะ smart card/ธนาคาร/วิทยุโทรศัพท์/OAM/connected civil industry ชื่อประเภทไม่พอ **พิสูจน์ทุกเงื่อนไขย่อย**

## 4. ข้อยกเว้นและหมายเหตุทั่วไป [S2]
- **Cryptography Note (หมายเหตุ 3):** ใช้กับ 5A002/5D002.a.1/b/c.1 ไม่ใช่ทั้งหมวด; **a** ต้องขายปลีกสาธารณะจากสต๊อกโดยไม่จำกัด (ร้าน/ไปรษณีย์/ออนไลน์/โทรศัพท์) ผู้ใช้เปลี่ยนเข้ารหัสไม่ได้ง่าย ติดตั้งเองได้โดยไม่พึ่งผู้ขายมาก และพร้อมแสดงข้อมูลต่อหน่วยงานไทย
- **b** ส่วนฮาร์ดแวร์/executable software ของสิ่งตาม a: security ไม่ใช่หลัก ไม่เปลี่ยน/เพิ่มเข้ารหัส ชุดลักษณะตายตัวไม่ปรับตามลูกค้า พร้อมข้อมูลส่วนประกอบ/สินค้าปลายทาง; เปิดนิยาม executable software ด้วย
- หมายเหตุย่อย a: สินค้าน่าสนใจต่อวงกว้าง ราคา/ข้อมูลฟังก์ชันครบก่อนซื้อโดยไม่ต้องปรึกษาผู้ขาย; พิจารณาจำนวน ราคา ทักษะ ช่องทาง ลูกค้าและวิธีปฏิบัติซัพพลายเออร์
- **หมายเหตุ 2** ของส่วน 2: ผู้ใช้นำติดตัวเพื่อใช้ส่วนตัว; **GISN**: security เป็นส่วนประกอบ/ฟังก์ชันของสินค้าอื่นก็ต้องเทียบส่วน 2
- **GSN หมวด 1–9:** a ขายปลีกทั่วไปตามเงื่อนไข และ c object code ขั้นต่ำของสินค้าที่อนุญาต **ไม่ปลดส่วน 2**; b in the public domain ไม่มีข้อจำกัดนั้นในถ้อยคำ **[ตีความตามข้อความ ไม่พบแนว DFT]** ไม่รับรองยกเว้นเอง
- **สาธารณสมบัติ NCL:** เปิดเผยโดยไม่จำกัดเผยแพร่ต่อ ลิขสิทธิ์ไม่ตัดสถานะอัตโนมัติ **ไม่ใช่ public domain ทางลิขสิทธิ์**; GTN มีข้อความสาธารณสมบัติ/วิจัยพื้นฐาน/ข้อมูลขั้นต่ำยื่นสิทธิบัตร ตรวจถ้อยคำและสิ่งที่ถ่ายโอน
- **OSS/repository:** พิสูจน์สิทธิเผยแพร่ต่อ/เงื่อนไขเข้าถึง แยก customization/เอกสารลับ/technical assistance; ลิขสิทธิ์ส่ง `thai-copyright-software`
- นิยาม software ใน NCL ใช้ถ้อยคำเกี่ยวกับการตรึงในสื่อจับต้องได้ แต่ ม.4 รวมสิ่งจับต้องไม่ได้และ CAC รวมอินเทอร์เน็ต **ไม่ตัดไฟล์ออกทั้งระบบ** [S1/S5]

## 5. การถ่ายโอน: ขอบเขตไทยและข้อจำกัด [S1/S5]

| วิธีส่ง | วิธีวิเคราะห์ |
|---|---|
| สื่อ/ฮาร์ดแวร์ | จำแนกอุปกรณ์และซอฟต์แวร์; ใบขนของจริง ศุลกากร ม.51–52; USB ไม่เป็น 0A–0C เพียงเพราะบรรจุไฟล์ |
| ดาวน์โหลด/อีเมล | CAC ข้อ 1 รวมอิเล็กทรอนิกส์; หนังสือห้ามรายกรณี ไม่พบใบอนุญาตหมวด 5; แจ้งศุลกากรในกลไกนี้เฉพาะสื่อ |
| SaaS/API/cloud | ไม่พบคำวินิจฉัยเฉพาะ; แยกใช้ระยะไกลออกจากรับ SDK/client/ข้อมูลเทคนิค คำว่า “บริการ” ไม่ยุติเรื่อง |
| source/repository/บุคลากร | ตรวจสิ่งเปิดให้เข้าถึง/ผู้รับ; ไม่พบ deemed export ไทยโดยสัญชาติอย่างเดียว; OSS ต้องพิสูจน์ GSN/GTN |
| ฝึกอบรม/ช่วยเทคนิค | CAC รวมทักษะ ความรู้ ข้อมูลเฉพาะ; ตรวจสัมพันธ์กับ DUI/หนังสือ DFT ไม่เหมารวมสอนวิศวกรรมทั่วไป |
| เนื้อหาต่างประเทศ | ให้ทนายเขตนั้นตรวจ re-export; NCL ไม่แทน EAR/EU/UK [S13] |

หมวด 5 ยังไม่ถูกประกาศใบอนุญาต ณ วันที่อ้างอิง **ไม่ปลด CAC/ทรัพย์สิน/กฎหมายเฉพาะ/สัญญา** ดู `wmd_trade_controls_act.md` §4/6

**ข้อสรุป ณ 9 ต.ค. 2569:** ซอฟต์แวร์/SaaS ที่ผลจำแนกไม่เข้า 0A/0B/0C และไม่มีหนังสือห้าม DFT รายกรณี = **ไม่ต้องขอใบอนุญาตส่งออก** (ระบอบ: ใบอนุญาตครอบคลุมเฉพาะ 0A/0B/0C; CAC รวมการส่งทางอิเล็กทรอนิกส์; หมวด 5 ยังไม่มีใบอนุญาต) — ผลนี้เปลี่ยนเมื่อ NCL แก้ไขหรือหนังสือ DFT รายกรณี ทบทวนทุกคราวก่อนสรุป

## 6. ลำดับตัดสินซอฟต์แวร์เข้ารหัส
1. ผังฟังก์ชัน → protocol/library/OSS → อัลกอริทึม/กุญแจ/จุดประสงค์
2. มีเพียงฟังก์ชันไม่นับหรือไม่ถึงเกณฑ์ → นอก **5A002.a เท่านั้น** ตรวจรายการอื่นต่อ; ไม่มีสเปก → ยังจำแนกไม่ได้
3. เทียบ a.1–a.4/5D002; พิสูจน์ Cryptography Note/ข้อเฉพาะ/GSN/GTN แยกกัน
4. ผล: นอกเกณฑ์ที่ตรวจ / ผ่านข้อยกเว้น / เข้าบัญชี / ข้อมูลไม่พอ ทุกผลตรวจใบอนุญาต/CAC/รายชื่อ/กฎหมายอื่น
5. เก็บหลักฐาน ผู้ทบทวน/เวอร์ชัน/วันที่; เปลี่ยนฟังก์ชัน วิธีส่งหรือ NCL ต้องจำแนกใหม่

## หลักการ
- จำแนกด้วยพารามิเตอร์ทางเทคนิค ไม่ใช่ชื่อผลิตภัณฑ์หรือพิกัดเพียงอย่างเดียว
- ระบุตรง ๆ ว่าประเด็นใดไม่มีนิยาม/แนวปฏิบัติ (คลาวด์ source code deemed export) แทนการเดา
- ถอดถ้อยคำ NCL จากต้นฉบับทุกครั้งก่อนส่งมอบเอกสารที่มีผลทางกฎหมาย
